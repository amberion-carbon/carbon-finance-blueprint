Two Approaches Compared

Both approaches assume 1 full-stack developer. The difference is how much of the actual coding Claude handles versus the human.

Approach A: Developer + Claude as Copilot
The developer writes code with Claude assisting via autocomplete, code generation, and debugging. The human makes all architectural decisions and does the integration work. Claude accelerates the coding but the developer is still the primary builder.

Dev responsibility: ~70% coding, architecture, debugging, deployment
Claude helps with: Boilerplate, repetitive CRUD, component generation, SQL queries, test writing
Approach B: Claude Code as Primary Builder
Claude Code generates the majority of the codebase from detailed prompts. The developer reviews outputs, makes corrections, handles edge cases, and manages deployment. Think of it as Claude doing 60-70% of the raw coding, with the developer steering, reviewing, and filling gaps.

Dev responsibility: Architecture decisions, prompt engineering, code review, testing, deployment, integration debugging
Claude builds: Database schema, API endpoints, UI components, forms, tables, dashboards, n8n workflow templates

Where Claude Code excels

CRUD operations
Creating, reading, updating, deleting records. This is 40-50% of the app. Claude generates these in minutes, not hours.
Database schema + migrations
Prisma models, SQL schemas, migration files. Claude can generate the entire data model from the blueprint spec.
UI components + forms
React components, table views, form validation. The repetitive UI work that eats developer hours.
API endpoint scaffolding
REST endpoints with validation, error handling, auth middleware. Claude generates consistent, well-structured APIs.

Where the developer is essential

Third-party API integration
Revolut, Wise, Deel, Google Workspace APIs require careful auth flows, error handling, and edge case management. Claude can scaffold, but a human needs to debug the real-world integration.
Business logic validation
Making sure the rate calculations match the spreadsheet exactly. Testing with real data. Catching the edge cases (partial months, mid-month rate changes, currency conversions).
Deployment + DevOps
Setting up hosting, CI/CD, environment variables, SSL, database backups. Claude can write configs but a human needs to manage the infrastructure.
Security review
Auth implementation, bank detail encryption, API key management, role-based access. Too critical to leave to AI alone.

Risks and Considerations

Claude Code limitations
Claude generates code that works in isolation but may not account for all integration edge cases. Bank APIs (Revolut, Wise) have strict requirements around idempotency, rate limits, and error handling that need human attention. Budget an extra 10-15% for integration debugging.
Code quality review is non-negotiable
Claude-generated code needs thorough review, especially for security (auth, encryption), financial calculations (rounding, currency), and data integrity (database constraints, transactions). The time savings come from generation speed, not from skipping review.
Scope creep risk
Because Claude can generate features quickly, there's temptation to add "just one more thing" per phase. Stick to the phased approach. Ship Phase 1, use it for a billing cycle, then iterate. Real usage reveals the real priorities.
Testing with real financial data
The billing calculations must match the spreadsheets exactly. Plan for at least one full billing cycle running in parallel (platform + spreadsheet) before cutting over. This adds ~2 weeks to the effective go-live timeline but prevents costly errors.

Recommended Approach

Start with Approach B (Claude Code Primary) for Phase 1
Get Phase 1 built in ~1.5 weeks. Run it alongside the spreadsheets for one billing cycle. If the developer is comfortable with the Claude Code workflow and the output quality is solid, continue with Approach B for remaining phases. If the code needs more human intervention than expected, shift to Approach A for the more complex phases (3 and 4). The two approaches aren't mutually exclusive. You can mix them per phase based on what works.
